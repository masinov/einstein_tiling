## Experiment pre-registration

### Proposition

Decide exactly the six bounded K16W formulas frozen by D-0173: `S1--`,
`S1-+`, `S2--`, `S2-+`, `S3--`, and `S3-+`.  The bytes and SHA-256 values,
not a regenerated Python expression graph, are the experiment.  Every file
has 187 assertions and retains complete K21Q, all 32 containment bounds,
closure, all 120 nonadjacent-pair predicates, and the 21 admitted
N38/K29O/N41/K31C/N42/K32S/K32A/N43/K33C constraints.

### Prior art and non-redundancy

The NLSAT/Z3 method and exact certificate boundary were audited before HC-31
and HC-34; no solver novelty is claimed.  HC-31's unbounded cells reached
resource stops.  HC-34 produced no solver evidence because its launcher
compared nondeterministically generated SMT-LIB text and its screen process
was reaped by the managed launch scope.  D-0174 forbade silent retry.  This
new user-authorized checkpoint is the first effective attempt on the six
byte-frozen, theorem-reduced cells.

### Outcome decisions

- A SAT result reopens only its named carrier cell, and only if the existing
  independent exact verifier certifies a rational model against the original
  geometry, selected charts/strand signs, and all 120 pair predicates.  An
  algebraic or unverifiable model leaves that cell open.
- Bare solver UNSAT is solver evidence only and does not close a cell without
  independently replayable exact evidence.  Six certified closures would be
  required to refute K16W.
- `unknown`, timeout, external resource stop, service failure, malformed
  result or missing result leaves only that named cell open/frozen.  No result
  class authorizes another ordering, rerun or budget increase.

### Stop rule and finite justification

Run the same two fixed concurrent batches as HC-34: first `S1--, S1-+, S2--`,
then `S2-+, S3--, S3-+`.  Each cell receives one Z3 5.0 QF_NRA ordering, a
three-hour internal timeout, external `/usr/bin/timeout` at 10,800 seconds
with 60-second kill grace, and a 32-GiB process memory parameter.  At most
three cells run concurrently: eighteen cell-hours and six elapsed solver
hours total.  There is no fallback formula, seed, alternate order, partial
cell, weakened predicate, retry or escalation.

The supervisor itself is a transient user service.  Each cell uses a new
process session, so failures are isolated.  A separately hosted screen only
tails logs.  Losing the viewport has no effect on solver ownership.

## Results

The gate passes before implementation.  A harmless host-native transient
user-service probe persists outside the managed command scope and exits
successfully.  The HC-35 runner authenticates all six frozen files before
starting any cell, refuses stale results or manifests, creates a new process
session for every cell, waits for every sibling before parsing results, and
writes an incremental launch manifest containing each PID and process group.

The exact screen-death signal from HC-34 is unavailable, but exception
cascade is excluded by the old supervisor's control flow: nonzero cell exits
were ordinary return codes and it waited for every sibling.  The managed
launch scope instead reaped screen and its remaining descendant when the
initiating command returned.  HC-35 removes that ownership path: a transient
user service owns the supervisor and a separate screen service only tails
logs.
